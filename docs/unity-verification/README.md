# Unity 逻辑验证工具（可复现）

这是**辅助验证工具**，不是作业本身的一部分（不影响 Unity 工程）。

本机没有安装 Unity 编辑器，为了尽可能验证 Unity 代码的正确性，这里用 .NET 8 +
手写的 UnityEngine 桩，**真实执行** `unity/Assets/Scripts` 下的业务逻辑与 uGUI 交互。

## 运行

```bash
# 可选：想让第 7 组“真实后端联调”通过，先启动 Go 后端
cd ../../backend && go run .

cd docs/unity-verification
dotnet run
```

输出示例（69 项全部通过）：

```
== 1. JSON 扫描 / 信封解析 ==
  PASS  取对象值
  PASS  不误取嵌套同名 key
  ...
== 7. 与真实 Go 后端联调 ==
  PASS  真实后端：创建问题成功
  PASS  真实后端：坐标往返一致
  PASS  真实后端：状态变为 in_progress
通过 69 项，失败 0 项
```

实测结果见 `../test-output/unity-behavior.txt`。

## 覆盖了什么

| 组 | 内容 |
| --- | --- |
| 1 | `JsonScan` / `Envelope`：嵌套同名 key、字符串内括号与转义、未闭合、HTML 响应 |
| 2 | 枚举线缆格式、BaseUrl 规范化（不带 http://、带尾斜杠、空值） |
| 3 | `IssueApi`：201/400/连接失败/非 JSON 的解析与错误文案、顶层数组列表 |
| 4 | 放置状态机：一次点击一个标记、标记坐标=命中点、取消移除、空标题拦截、提交成功保留、失败保留可重试、历史恢复越界跳过、颜色随状态变化 |
| 5 | 场景构建：表面数量、所有表面都有 Collider |
| 6 | HUD：射线→表单打开→填表→点提交→成功提示；失败提示；UI 点击不误放；后端不可用提示 |
| 7 | 真实 Go 后端：创建→改状态→再查询闭环 |

## 它不能证明什么

- 不能替代在 Unity Editor / 真机上的运行（渲染、真实物理射线、真实 uGUI 事件系统、字体）。
- 桩的行为可能与 Unity 有细微差异（开发过程中就修正过 3 处桩自身的 bug）。
- 因此 README 第 7 节如实注明了“Unity 工程未在编辑器中运行验证”。
